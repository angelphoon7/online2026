## Reproduce

From the repository root, with Foundry and the configured Solidity compiler installed:

```bash
forge test --gas-report --color never
forge test --gas-report --color never --match-test test_settles_without_participant_online
forge test --gas-report --color never --match-test test_buyer_seller_chain_completes
forge test --gas-report --color never --match-test test_three_way_reshuffle_succeeds
forge test --gas-report --color never --match-test test_seed_is_live_then_settles_without_participants
```

On this Windows workspace the executable is `.tools/foundry/forge.exe`. These commands run local tests and do not broadcast transactions or spend Arc USDC. The reports are saved verbatim apart from UTF-8 encoding and newline normalization; suite timing and execution order can vary between runs.

[`full-suite.txt`](full-suite.txt) records **32 passed, 0 failed, 0 skipped**. Four filtered runs each execute one passing test and report exactly one `settle` call. ## Fixtures and scope

The first three scenarios are in [`test/Settlement.t.sol`](../../test/Settlement.t.sol), using [`Fixture.sol`](../../test/helpers/Fixture.sol). Each participant has one intent. The three-party cycle receives adjacent pairs; the open chain has a pure buyer, one swapper and a pure seller. The seller requests exactly zero tickets and has none of the three optional flags enabled. This three-party unit test is distinct from the four-party recorded act-two transaction.

The twelve-ticket scenario is in [`test/SeedDemo.t.sol`](../../test/SeedDemo.t.sol), with intents generated by [`script/SeedDemo.s.sol`](../../script/SeedDemo.s.sol). Each participant offers and receives four tickets, with all three optional flags enabled. The test also prepares another round after settlement; those preparation calls are separate from its single measured `settle` call.

The optional-constraint count is the sum of true cohesion/adjacency flags across intents. It is not a count of SLOADs, loop iterations, or all mandatory contract validations. Required validity, custody, event/mask, exact-count, budget, conservation, balance and capacity checks remain active. Tickets, optional constraints and fixture details vary together, so the rows do not isolate the incremental cost of a single constraint.

The function-level report excludes separate setup calls such as minting, approvals, deposits and commits; it measures `settle` in the respective local test's execution context. Do not substitute a whole-test gas total, a configured gas limit, or the aggregate average across expected reverts. The full report also contains deployment rows, but this table makes no deployment-cost claim.

These measurements are not mainnet estimates, Arc receipt `gasUsed`, or USDC transaction fees. Arc uses a different USDC implementation, and the actual transaction state and gas price matter. Refresh the reports and README together after changing contracts, fixtures or compiler settings.
